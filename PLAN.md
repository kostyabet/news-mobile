# PLAN.md — Vazon News: план реализации недостающего функционала

## Анализ покрытия БД

### Реализовано (Backend + Mobile)

| Сущность БД | Backend API | Mobile |
|---|---|---|
| **User** (auth) | `POST /users`, `POST /users/login`, `POST /users/refresh` | login, register экраны |
| **UserInfo** (profile) | `GET/PATCH/DELETE /profile/:id`, `POST /profile/:id/avatar` | profile экран, редактирование |
| **UserRole** | `GET /user-roles` | dropdown при регистрации |
| **Article** | CRUD + `/my` + upload image | лента, поиск, детали, создание/редактирование |

### Не реализовано

| Сущность БД | Backend | Mobile | Описание |
|---|---|---|---|
| **Comment** | нет | нет | Комментарии к статьям (с вложенностью через `c_parent`) |
| **Reaction** | нет | нет | Реакции на статьи (лайк/дизлайк и т.д.) |
| **Subscription** | нет | нет | Подписка на авторов |
| **Notification** | нет | нет | Уведомления пользователей (с типами и статусами) |
| **Settings** | нет | частично (локально) | Серверные настройки (тема, язык, email/push уведомления) |
| **Category** | нет | нет | Категории статей |
| **Tag** | нет | нет | Теги статей |
| **ArticleCategory** | нет | нет | Привязка статей к категориям (M2M) |
| **ArticleTag** | нет | нет | Привязка статей к тегам (M2M) |
| **ArticleStatus** | используется | фильтров нет | Статусы статей (draft/published/etc) |
| **Language** | нет | нет | Язык статьи (серверная привязка) |

# Fixes

## ~~Scroll update on News page and in Profile~~ DONE
Необходимо реализовать функционал обновления главной странице и на странице профиля(личного и по id) по скролу вверх.
Нужно сделать так, что если поле поиска уже активно (оно также открывается при скроле вверх) и пользователь
всё равно ещё скролит вверх то там появляется иконка загрузки и мы обновляем данные на главной страниец и отображаем их пользователю.
Необходимо оформить всё красиво и в соответствии со стилистикой приложения. При протягивании вверх пользователь должен понимать, что он обновит данные
Когда пользователь отпустит скролл нужен какой-то индикатор, что данные загружаются. Индикатор пропадёт по окончанию загрузки.

## ~~Main page skeleton~~ DONE

## ~~Article loading~~ DONE
Когда пользователь нажимает на артикл, то на бек улетает запрос, нужно, чтобы до того как мы точно убедимся, что артикла нет, то пользователю показывался какой-то loading.
Сейчас, как я понимаю, пока артикл не загружен то там где-то null или пусто и он пишет текст, что article не найден, но на самом деле может просто идёт запрос на бек с получением данных из кеша или ещё что-то.
